Skill synchronization pulls the repository's default branch rather than the release
tag, so a synchronized Skill tracks the pushed repository state and not necessarily
the installed binary's version. That is inherent to `npx skills add <repo>`.

## Provider Evidence

The synthetic Codex record cannot produce structured provider evidence, so the
`healthy` and `confirmed_exhausted` classification branches were not exercised live
in this run. `internal/quota/codex.go` is unchanged in `1.0.3`, and the guard's
observation path is behavior-identical after the apply-mode removal, so the
authorized production evidence recorded for `1.0.0` and the targeted `1.0.1` quota
smoke remain the qualifying evidence for that surface.

## Scope and Redaction

This artifact contains no Management key, provider token, cookie, authorization
header, raw auth file, confirmation token, production hostname, or account
identifier. No production deployment was written to at any point; the only
Management writes went to the disposable loopback instance and were restored.
